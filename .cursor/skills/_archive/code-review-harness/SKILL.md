# 종합 코드 리뷰 하네스

**정본**: [protocols/README.md](../../../protocols/README.md) **7단계(리뷰어)** — 기획·포트·유스케이스 정합은 [유리 주도, 시몬 보조](../../../protocols/README.md). 레이어 규칙: [architecture.mdc](../../rules/architecture.mdc), 상시 규칙: [shapez2-core.mdc](../../rules/shapez2-core.mdc).

**관계**: 전역 절차 [shapez2-harness](../shapez2-harness/SKILL.md), IDE [cursor-shapez2-harness](../cursor-shapez2-harness/SKILL.md). 이 스킬은 **읽기·감사·리포트**에 초점을 두고, 대규모 수정은 플랜·PR로 쪼갠다.

채팅에서 켜려면 `@code-review-harness` 또는 에이전트에 이 Skill을 포함한다.

## 병렬 감사 팀

동일 **브리프**(리뷰 범위: 커밋/PR/경로 목록, 목표, 금지: 예. 솔버 동작 무분별 변경 금지)를 네 감사자에게 전달한다. 감사자는 **서로의 초안을 읽지 않은 채** 이슈만 내면 편향이 줄어든다.

| 태그 | 초점 | 페르소나 정렬 | 산출물(반드시) |
|------|------|----------------|----------------|
| `[아키텍처]` | 레이어 방향, domain/application/adapters 경계, 중복·드리프트 | [유리](../../../persona/yuri.md) + [architecture.mdc](../../rules/architecture.mdc) | 위반·의심 지점 목록: **경로:줄**, 근거 한 줄, 심각도 |
| `[보안]` | 인증·세션·CSRF, SQL/OS 인젝션, 경로·SSRF, 비밀 하드코딩, 직렬화/역직렬화 | [아다](../../../persona/ada.md)(I/O 경계) + [AGENTS.md](../../../AGENTS.md) 비밀 규칙 | 취약 **패턴**·완화 권고(가능하면 CWE/OWASP 분류) |
| `[성능]` | 핫 경로, N+1, 동기 I/O, 불필요 복잡도·자료구조 | (공통) + 측정 가능한 가설 | 병목 가설·**재현/프로파일** 제안, 빠른 승리 vs 조사 필요 구분 |
| `[스타일]` | `ruff`/`mypy`/`black`, 타입·네이밍·가독성 | [렉스](../../../persona/rex.md) | 도구 요약 + 도구 밖 **일관성** 이슈 |

## 통합 리드

| 태그 | 역할 | 페르소나 정렬 |
|------|------|----------------|
| `[통합]` | 네 감사 산출물 **병합·중복 제거·우선순위** → 단일 리포트 확정 | [유리 주도, 시몬 보조](../../../protocols/README.md)(리뷰어 축) |

`[통합]`은 다음만 수행한다: 이슈 ID 부여, P0/P1/P2, 리포트 목차 고정, **상충 시** 아키텍처·보안 > 성능 > 스타일 순으로 기본 판단(예외는 브리프에 명시).

## 병렬 실행(권장)

- [ ] 브리프 1페이지: 범위, 링크, 비목표, 터치 금지 경로.
- [ ] **병렬**: Cursor **서브에이전트·백그라운드 태스크** 네 갈래에 동일 브리프(컨텍스트 분리: [cursor_usage.md](../../../documents/ai/manuals/cursor_usage.md)).
- [ ] `[스타일]`은 가능하면 `ruff check .`, `mypy .`, `black --check .` (또는 프로젝트 표준)을 **실행**하고 요약한다. 못 하면 미실행 사유.
- [ ] 완료 후 `[통합]`이 한 파일(또는 한 메시지)로 합친다.

단일 스레드만 쓸 때: 네 섹션을 **순서 고정**(아키텍처 → 보안 → 성능 → 스타일)으로 쓰되, 각 섹션 작성 중에는 다른 섹션을 인용하지 않는다. 마지막에 `[통합]`.

## 통합 리포트 목차(필수)

저장 권장: `documents/reports/` (관측·리뷰 산출물; [문서 권위](../../../AGENTS.md)에 따라 CANON이 아님).

```markdown
# 코드 리뷰: <범위 한 줄>

## 메타
- 범위·리비전·감사 일시
- 참가 태그 및 병렬 여부

## 요약 (P0만)
- ...

## 아키텍처
- ID, 경로, 심각도, 요약, 권고

## 보안
- ...

## 성능
- ...

## 스타일·정적 분석
- 도구 결과 요약, 잔여 이슈

## 통합 백로그 (우선순위)
| ID | 우선순위 | 영역 | 요약 | 담당 제안 |
```

## 감사자 미니 체크리스트

**`[아키텍처]`**

- [ ] domain에 I/O·프레임워크 침입 없음.
- [ ] application이 구체 adapter import 없음.
- [ ] 솔버·그래프·UI 개념 혼동 없음([graph_ui.md](../../../documents/ai/manuals/graph_ui.md) 등 브리프에 포함 시).

**`[보안]`**

- [ ] 비밀·토큰·키가 코드/로그에 없음.
- [ ] 사용자 입력이 쿼리·경로·HTML에 안전하게 바인딩.
- [ ] 권한·CSRF·세션 사용이 Django 관례와 맞는지(해당 시).

**`[성능]`**

- [ ] 루프 내 I/O·중복 쿼리·과도한 알로케이션.
- [ ] 측정 없는 단정 지양; “프로파일 후 판단” 태그.

**`[스타일]`**

- [ ] 린트·타입·포맷; [AGENTS.md](../../../AGENTS.md) 검증 순서와 정합.

## 구현과의 경계

리뷰 하네스 **자체가 구현 승인을 대체하지 않는다**. P0/P1은 플랜·티켓·PR로 넘기고, [persona-dialogue.mdc](../../rules/persona-dialogue.mdc) 3단계로 수정한다.
