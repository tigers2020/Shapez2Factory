# /goal 참고 — 평가 메커니즘과 자율 워크플로 비교

## 다른 자율 워크플로와의 비교

세 방식 모두 프롬프트 사이에서 현재 세션을 계속 굴린다. 다음 턴을 무엇이 시작하는지로 고른다.

| 방식 | 다음 턴 시작 시점 | 중단 시점 |
|---|---|---|
| `/goal` | 이전 턴이 끝났을 때 | 평가가 조건 충족을 확인했을 때 |
| `/loop` | 시간 간격이 지났을 때 | 사용자가 멈추거나 작업이 끝났다고 판단할 때 |
| Stop hook | 이전 턴이 끝났을 때 | 사용자 스크립트/프롬프트가 결정할 때 |

- `/goal` 과 Stop hook 은 둘 다 매 턴 뒤에 발동한다. `/goal` 은 **세션 범위 단축키** — 조건을 입력하면
  그 세션에서만 활성. Stop hook 은 설정 파일에 살며 그 범위의 모든 세션에 적용되고, 결정형 검사는
  스크립트로, 모델 평가형은 프롬프트로 돌릴 수 있다.
- Auto 모드는 한 턴 안의 tool 호출을 자동 승인할 뿐 새 턴을 시작하지 않는다. `/goal` 은 매 턴 뒤 조건을
  확인하는 별도 평가기를 더해, 작업하는 모델이 아니라 신선한 판단으로 완료를 결정한다. 둘은 상호 보완적:
  auto 모드는 per-tool 프롬프트를, `/goal` 은 per-turn 프롬프트를 없앤다.

## 평가가 동작하는 방식

- 매 턴이 끝날 때마다 조건과 지금까지의 대화를 평가에 넘긴다. 평가는 yes/no 결정과 짧은 사유를 돌려준다.
- `no` → 계속 작업하라는 신호이며 사유를 다음 턴 가이드로 포함한다.
- `yes` → 목표를 해제하고 transcript에 achieved 항목을 기록한다.
- 평가는 **tool을 호출하지 않으므로** 이미 surfacing된 것만 판단할 수 있다.
  Cursor 적응: 작업 에이전트가 검증을 실행해 출력을 대화에 남기고, 그 출력만으로 판정한다.
  독립성을 높이려면 readonly 서브에이전트(빠른 모델)에 surfaced 증거만 주고 판정을 받는다.

## 비대화형 실행

비대화형/데스크톱/Remote Control에서도 동작한다. CLI에서 `-p` 로 목표를 주면 단일 호출에서
조건 충족까지 루프를 돈다:

```
claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"
```

조건 충족 전에 멈추려면 Ctrl+C 로 중단한다.

## 세션 재개

세션 종료 시점에 활성이던 목표는 `--resume`/`--continue` 로 재개하면 복원된다.
조건은 이어지지만 turn count·타이머·토큰 기준선은 재개 시 초기화된다.
이미 달성/해제된 목표는 복원되지 않는다.

## 요구 사항 (native /goal)

Claude Code native `/goal` 은 v2.1.139+ 가 필요하고, hooks 시스템 일부이므로 trust 다이얼로그를
수락한 워크스페이스에서만 동작한다. `disableAllHooks` 또는 managed `allowManagedHooksOnly` 가
설정되면 사용 불가하며, 그 경우 명령이 이유를 알려준다.

Cursor 적응판은 hooks가 아니라 상태 파일 + 자율 루프로 동작하므로 위 제약을 받지 않는다.
