**Status:** Approved 2026-05-23 (design review)  
**Owner:** asteroid-lab / RTTP

## Purpose

RTTP v0.2 closes **RTTP-G8 replay on/off parity**: running `run_rttp_pipeline` with a replay sink enabled must produce the **same** optimization outcome as with recording disabled.

**This slice is not about replay UX.** Goals:

```text
Prove: recorder present → PipelineResult unchanged
Defer: DB persistence, UI timeline, NDJSON export, full Sequence 3B event matrix
```

---

## Phased delivery

| Phase | Scope | Merge gate |
|-------|--------|------------|
| **PR-A** | In-memory / null sink; pipeline-only hooks; G8 unit tests | RTTP-G8 v0.2 |
| **PR-B** | `DbRttpReplaySink` → `ReplayRecorder`; `solver_runtime_entry` wiring; DB smoke | RTTP-RB1, RTTP-RB2 |

PR-B must not start until PR-A targeted tests are green.

---

## Non-goals (v0.2)

- Replay artifact as solver / candidate / probe / commit / validation **input**
- New `validation.*` or `rttp.*` wire `event_type` strings in PR-A
- Hooks inside `candidate_generator`, `incremental_commit`, or `local_lns` (PR-A)
- Lab UI timeline, NDJSON export, optimization replay golden fixtures
- Sequence 3B full event matrix (separate track after G8 is proven)

---

## Approach (C′)

Reuse existing replay DTOs and registered wire types; do **not** introduce RTTP-only event enums in PR-A.

| Layer | PR-A | PR-B |
|-------|------|------|
| Event payload | `SnapshotEventDTO` (`django_apps.asteroid_lab.services.dto`) | same |
| Wire `event_type` | `django_apps.asteroid_lab.replay.event_types` (registered in `SNAPSHOT_EVENT_TYPES`) | same |
| Persistence | `InMemoryRttpReplaySink` / `NullRttpReplaySink` only | `DbRttpReplaySink` wraps `ReplayRecorder` |
| Forbidden | `optimization/` imports `ReplayRecorder`, ORM, `ReplayFrame` | reading replay rows inside `run_rttp_pipeline` |

**Why not `ReplayEventType.route_probe.succeeded`:** that value is **not** in `SNAPSHOT_EVENT_TYPES`; `ReplayRecorder.record_event` calls `assert_registered_event_type` and would raise. Aligning `ReplayEventType` with `event_types.py` is **Sequence 3B or PR-B**, not PR-A.

## §1 — Recorder port (PR-A)

### Module

`django_apps/asteroid_lab/optimization/replay_sink.py` (name may be `replay_port.py`; keep one module).

### Protocol

```python
from typing import Any, Protocol

class RttpReplaySink(Protocol):
    def record(self, event: SnapshotEventDTO) -> Any: ...
```

Implementations may return `None`, a dict, or any other value. **`RttpReplaySink.record()` return value is ignored** — `run_rttp_pipeline` must not branch on it (see §3 `WeirdSink` test).

### Implementations

| Class | Behavior |
|-------|----------|
| `NullRttpReplaySink` | no-op |
| `InMemoryRttpReplaySink` | append to `events: list[SnapshotEventDTO]` |

PR-B adds:

| Class | Behavior |
|-------|----------|
| `DbRttpReplaySink` | `ReplayRecorder(track_id, policy).record_event(event)`; implements same protocol |

### Pipeline API

```python
def run_rttp_pipeline(
    inp: OptimizationInput,
    *,
    policy: ExtractorPlacementPolicy = ...,
    replay_sink: RttpReplaySink | None = None,
) -> PipelineResult: ...
```

- `replay_sink is None` → treat as `NullRttpReplaySink()`.

### Import boundary (PR-A)

```text
optimization/  MUST NOT import:
  ReplayRecorder, ReplayFrame, ReplayTrack, Django ORM
```

`SnapshotEventDTO` and `event_types` constants are allowed (DTO + string registry only).

### Forwarding rule (PR-A)

`replay_sink` is passed only to `run_rttp_pipeline` orchestration helpers in `pipeline.py`. It is **not** passed into `generate_candidates`, `select_genome`, `incremental_commit`, or `run_local_lns`.

## §2 — Hook points (PR-A, orchestration only)

All events are emitted from **`pipeline.py` only** (four milestones). No per-candidate or per-probe frames in PR-A.

Payload discipline:

- `cell_overlay_json` and `full_map` stay **empty** in PR-A (allocation smoke without map serialization).
- Distinguish RTTP via `title` and `metrics_json`, not new wire types.

### Event table

| When | `event_type` (`event_types.py`) | `phase` | `title` |
|------|----------------------------------|---------|---------|
| Pipeline start | `routing.probe_started` | `rttp_pipeline` | `RTTP pipeline started` |
| After `generate_candidates` | `candidate.generated` | `candidate_generation` | `RTTP candidates generated` |
| After `select_genome` | `ga.best_updated` | `genome_fitness` | `RTTP selection complete` |
| After commit + validation | `routing.committed` | `incremental_commit` | `RTTP commit complete` |

**Do not** emit `reconstruction.map_complete` for validation — it is registered but semantically reconstruction; using it under a validation phase would confuse later UI/analytics.

**Do not** add a separate post-validation hook in PR-A. Final state is folded into the last row:

`routing.committed` `metrics_json` includes at minimum:

```python
{
    "committed_ids": list[str],      # commit_result.committed_ids
    "commit_order": list[str],       # genome.commit_order
    "validation_passed": bool,
    "conflict_count": int,           # len(commit_result.conflicts)
    "normal_count": int,             # generation.normal_count
}
```

### Deferred wire types

```text
PR-A does not introduce validation.* or rttp.* event types.
Dedicated validation / RTTP-specific event names → PR-B or Sequence 3B.
```

## §3 — RTTP-G8 v0.2 gates (PR-A tests)

**File:** extend `tests/unit/asteroid_lab/test_rttp_pipeline_greenfield.py` and/or add `tests/unit/asteroid_lab/test_rttp_replay_parity.py`.

### G8 parity

```python
off = run_rttp_pipeline(inp, replay_sink=NullRttpReplaySink())
sink = InMemoryRttpReplaySink()
on = run_rttp_pipeline(inp, replay_sink=sink)

assert sink.events  # non-empty; recording actually ran
assert pipeline_results_equal(off, on)
```

### `pipeline_results_equal`

| Check | Notes |
|-------|--------|
| `off == on` | frozen `PipelineResult` equality (v0.1 baseline) |
| `commit_result.committed_ids` | explicit |
| `genome.commit_order` | selection commit order (there is no separate `selected_candidate_ids` field on `PlacementGenome`) |
| `validation_passed`, `normal_count` | explicit |

**Forbidden:** add replay frame counts or sink metadata to `PipelineResult` — that would break `off == on`.

`solver_summary` scalar parity is **PR-B** (runtime entry integration), not PR-A unit scope.

### Return-value ignored

`test_rttp_replay_sink_return_value_is_ignored`:

```python
class WeirdSink:
    def record(self, event: SnapshotEventDTO) -> dict[str, object]:
        return {"try_to_influence_solver": True}

# run_rttp_pipeline(..., replay_sink=WeirdSink()) vs Null → same PipelineResult
```

### Optional architecture test

`test_rttp_pipeline_does_not_pass_sink_to_layer_functions` — grep/static guard that `replay_sink` is not forwarded into `generate_candidates` / `incremental_commit` signatures (if enforced via code structure, document in plan).

## §4 — PR-B (persistence sketch)

### Wiring

```text
solver_runtime_entry._run_rttp_solver_for_map_input
  → ensure ReplayTrack on SolverRun (existing shell)
  → DbRttpReplaySink(track_id, policy)
  → run_rttp_pipeline(..., replay_sink=sink)
```

### Gates

| Gate | Requirement |
|------|-------------|
| **RTTP-RB1** | `DbRttpReplaySink` persists `ReplayFrame` rows but `solver_summary` dict (keys/scalars used today) is **unchanged** vs null sink run on same input |
| **RTTP-RB2** | `run_rttp_pipeline` and optimization layers **never** read `ReplayFrame` / replay payload for decisions (pattern: `test_persistence_does_not_read_replay_frames`) |

### Out of scope (PR-B)

- Lab UI timeline playback
- NDJSON export
- Full Sequence 3B event matrix
- `route_probe.succeeded` / `ReplayEventType` alignment unless required for a specific frame (separate change)

## Risks

| Risk | Mitigation |
|------|------------|
| Reusing `ga.best_updated` for selection semantics | `title` + `metrics_json.commit_order` document RTTP meaning |
| Heavy `SnapshotEventDTO` allocation | empty overlays in PR-A; parity test proves correctness not perf |
| Phase string `rttp_pipeline` not in `ReplayPhase` enum | `SnapshotEventDTO.phase` is free `str`; product enum alignment optional in 3B |
| Black / CI drift | no change to pyproject in PR-A unless pinning requested separately |
