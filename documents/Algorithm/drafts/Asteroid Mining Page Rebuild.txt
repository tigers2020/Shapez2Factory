# 왜 MILP/Gurobi 버려야 하냐

현재 네가 만들려는 건 단순 placement 문제가 아님.

문제 축이 4개 겹쳐 있음:

```text id="3783ac"
1. extractor placement
2. extension topology
3. transport routing
4. exterior connectivity preservation
```

그리고 여기에:

```text id="dl2ndh"
- asteroid topology
- interior void
- transport isolation
- belt / pipe separation
- merge-aware trunk
```

까지 들어감.

이걸 MILP로 가면:

```text id="9okwbo"
variable explosion
constraint explosion
routing combinatorics
```

터진다.

Gemini가 설명한 내용 자체는 일반론적으로 맞음. fileciteturn1file0  
근데 Shapez2 asteroid는 routing graph가 너무 동적이라서:

```text id="qfaor2"
placement 최적화 + route feasibility
```

가 강하게 결합됨.

즉:

```text id="paxu5o"
"광부 많이 놓기"
```

만 풀면 안 되고:

```text id="l63w0o"
"실제로 외부 trunk까지 연결 가능한 상태"
```

까지 같이 풀어야 함.

# 네 프로젝트에 더 맞는 구조

```text id="h97ete"
GA + Constraint-aware Local Solver
```

형태.

# 추천 아키텍처

## 1단계 — Pattern Library

DP를 “전체 문제”에 쓰면 안 됨.

대신:

```text id="hx3ycq"
small local optimal templates
```

를 만드는 데만 써야 함.

예:

```text id="5180te"
Extractor + extensions
```

패턴들을 미리 구움.

예시:

```text id="0i0qla"
1 extractor
2 extension
3 extension chain
T-shape
corridor-safe
rim-safe
```

등.

즉:

```text id="eln0cm"
DP = local pattern compiler
```

로 사용.

---

# 2단계 — Genome 설계

유전자 단위를:

```text id="58xy1x"
cell
```

로 하면 망함.

반드시:

```text id="du68jv"
placement bundle
```

단위여야 함.

즉:

```text id="1hug5z"
gene = prevalidated extractor bundle
```

이어야 함.

예:

```python id="yvsbgg"
Gene:
    extractor_coord
    output_dir
    extension_pattern_id
    transport_kind
```

---

# 3단계 — Feasibility-first

이게 핵심.

기존 v1/v2 문제는:

```text id="2ep1np"
placement 먼저
routing 나중
```

이라서 다 무너졌음.

반드시:

```text id="fb0mps"
candidate 생성 순간
↓
즉시 route feasibility probe
```

해야 함.

즉:

```text id="8m82x8"
"놓을 수 있는가?"
```

가 아니라:

```text id="1sxoss"
"외부 trunk 연결 가능성이 있는가?"
```

를 먼저 봐야 함.

---

# 4단계 — Routing은 “cheap approximate”

여기서 중요한 거:

최초 routing은:

```text id="3mrysd"
완벽한 최적 route
```

찾지 말고:

```text id="cujfmj"
fast connectivity feasibility
```

만 해야 함.

예:

```text id="363oil"
bounded BFS
lightweight A*
distance-to-margin heuristic
```

정도.

---

# 5단계 — Fitness 함수

여기서 진짜 중요.

단순:

```text id="pt38p8"
extractor count
```

만 쓰면 spaghetti 폭발함.

반드시:

```text id="00sgzl"
fitness =
+ extractor_score
+ extension_efficiency
+ external_connectivity
- orphan_transport
- internal_transport_cost
- congestion
- dead_stub
- isolated_cluster
```

구조여야 함.

# 가장 중요한 부분

## “Evolution 대상”이 route가 되면 안 됨

이거 매우 중요.

잘못하면:

```text id="0vt6nm"
GA가 belt까지 직접 진화
```

시키는데 이러면 탐색 공간 폭발함.

대신:

```text id="9zxauc"
GA는 placement topology만 진화
routing은 deterministic local solver
```

여야 함.

즉:

```text id="qsznqe"
GA:
"어디에 어떤 bundle 놓을까?"

Router:
"그걸 연결 가능한가?"
```

분리.

```text id="6nmctb"

+

```

동시 평가 구조여야 함.
