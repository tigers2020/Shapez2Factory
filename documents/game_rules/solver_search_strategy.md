# 솔버 탐색 전략: 최단 경로는 연산 비용 기반

## 왜 단순 재귀 분해가 부족할 수 있는가

동일 목표 도형에 대해 여러 생산 경로가 존재한다.

예: `RcCuRcCu` 는 대략 다음 같은 후보가 있다.

- 네 분면 절단 + 적층 반복
- 넓은 단색 도형 두 개 → 회전/정렬 후 **swap halves**
- 반쪽 생성 후 적층

따라서 “한 번에 정해진 분해 규칙”만으로는 최소 빌딩/최소 단계를 보장하기 어렵다.

## 알고리즘 후보

| 방법 | 언제 유리한가 |
| --- | --- |
| **BFS** | 연산 비용이 균일하고 상태 공간이 작을 때 |
| **Dijkstra** | 연산·건물·처리량 페널티 등 **가중 비용**이 다를 때 |
| **A*** | 목표 shape와 현재 shape의 **분면 불일치** 등을 휴리스틱으로 쓸 때 |

## 코드베이스에서의 위치(참고)

일부 탐색·매칭 로직은 이미 `shapez_solver` 단위 테스트·서비스에 있다 (예: 인벤토리/프리빌트 패턴 검색). 범용 **목표 shape까지의 최소 비용 그래프 탐색** 레이어를 새로 쌓는 것은 별도 플랜에서 다룬다.

## 메모

- 상태는 정규화된 `Shape` + 필요 시 **페인트 자원 벡터**로 잡을 수 있다 ([operation_color_mixer.md](operation_color_mixer.md)).
- 휴리스틱은 **합허적(admissible) 여부**를 검토해야 한다(과소추정이면 A*가 최적성을 잃을 수 있음).
