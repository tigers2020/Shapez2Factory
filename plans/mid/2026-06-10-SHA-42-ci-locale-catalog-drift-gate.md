# Plan: Add locale catalog drift gate to CI

## Source Issue

- Linear: SHA-42
- Status at planning time: Todo
- Priority: Mid

## Problem

Korean locale catalogs are generated by `scripts/build_locale_ko.py` and committed under `locale/ko/LC_MESSAGES/`. GitHub Actions never regenerates these files or fails when they drift from current template/JS gettext sources. PRs can add or change translatable strings while leaving stale committed catalogs and still pass CI.

## Scope

Add a CI or pytest gate that regenerates locale catalogs and fails when `locale/ko/LC_MESSAGES/*` would change. Document the gate in `documents/ai/manuals/testing.md` if needed.

## Non-goals

- Translating missing KO strings (SHA-43)
- Replacing the polib-based builder with GNU gettext
- Changing runtime Django locale middleware behavior

## Implementation Plan

1. Read `scripts/build_locale_ko.py` invocation and output paths (`django.po`, `django.mo`, `djangojs.po`, `djangojs.mo`).
2. Add contract test or CI step:
   ```bash
   python scripts/build_locale_ko.py
   git diff --exit-code locale/ko/LC_MESSAGES/
   ```
3. Wire into `ci.yml` as new matrix task (e.g. `locale-catalog`) or pytest marker in test-fast.
4. On first gate landing, regenerate and commit current catalogs if drift exists (may be separate commit in same PR).
5. Update `documents/ai/manuals/testing.md` § Locale if CI matrix is documented there.

## Files / Areas Likely Affected

- `.github/workflows/ci.yml`

- `locale/ko/LC_MESSAGES/`
- `tests/unit/test_build_locale_ko_strict.py` (reference)
