# Plan: CI never verifies committed locale/ko .po/.mo match build_locale_ko.py output

## Source Issue

- Linear: SHA-42
- Status at planning time: Todo
- Priority: Mid

## Problem

Korean locale catalogs are generated by `scripts/build_locale_ko.py` and committed under `locale/ko/LC_MESSAGES/`. GitHub Actions never regenerates these files or fails when they drift from current template/JS gettext sources.

## Scope

Add a CI or pytest gate that regenerates locale catalogs and fails when `locale/ko/LC_MESSAGES/*` would change. Document the gate in `documents/ai/manuals/testing.md` if needed.

## Non-goals

- Translating missing KO strings (SHA-43).
- Replacing the polib-based builder with GNU gettext.
- Changing runtime Django locale middleware behavior.

## Implementation Plan

1. Add contract test (e.g. `tests/unit/test_locale_catalog_freshness.py`) that runs `python scripts/build_locale_ko.py` and asserts `git diff --exit-code locale/ko/LC_MESSAGES/`.
2. Wire check into `.github/workflows/ci.yml` as matrix task or part of `test-fast`.
3. Regenerate and commit current catalogs once if builder output differs on `master`.
4. Update `documents/ai/manuals/testing.md` § Locale with the freshness gate command.
5. Confirm `tests/unit/test_build_locale_ko_strict.py` remains for `--strict` KO dict completeness (orthogonal concern).

## Files / Areas Likely Affected

- `scripts/build_locale_ko.py`
- `locale/ko/LC_MESSAGES/django.po`, `django.mo`, `djangojs.po`, `djangojs.mo`
- `.github/workflows/ci.yml`
- `tests/unit/test_locale_catalog_freshness.py` (new)
- `documents/ai/manuals/testing.md`

## Validation Plan

- lint: `ruff check .`
