# Plan: CI locale catalog drift gate

## Source Issue

- Linear: SHA-42
- Status at planning time: Todo
- Priority: Mid

## Problem

Korean locale catalogs are generated by `scripts/build_locale_ko.py` and committed under `locale/ko/LC_MESSAGES/`. GitHub Actions never regenerates these files or fails when they drift from current template/JS gettext sources. A PR can add or change `{% trans %}` / JS `gettext()` strings while leaving stale committed catalogs and still pass CI.

## Scope

Add a CI or pytest gate that regenerates locale catalogs and fails when `locale/ko/LC_MESSAGES/*` would change. Document the gate in `documents/ai/manuals/testing.md` if needed. Regenerate and commit current catalogs once the gate lands.

## Non-goals

- Translating missing KO strings (tracked separately in SHA-43)
- Replacing the polib-based builder with GNU gettext
- Changing runtime Django locale middleware behavior

## Implementation Plan

1. Add a contract test (e.g. `tests/unit/test_locale_catalog_freshness.py`) that runs `python scripts/build_locale_ko.py` and asserts no diff under `locale/ko/LC_MESSAGES/`.
2. Wire the check into `.github/workflows/ci.yml` as a new matrix task or prepend to an existing fast-test job.
3. Run the builder locally, commit regenerated `django.po`, `django.mo`, `djangojs.po`, `djangojs.mo` if drift exists on current `master`.
4. Update `documents/ai/manuals/testing.md` § Locale to document the drift gate alongside existing `build_locale_ko.py --strict` notes.
5. Verify locally: `python scripts/build_locale_ko.py` followed by `git diff --exit-code locale/ko/LC_MESSAGES/`.
