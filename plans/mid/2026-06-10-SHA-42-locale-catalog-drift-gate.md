# Plan: CI gate for Korean locale catalog freshness

## Source Issue

- Linear: SHA-42
- Status at planning time: Todo
- Priority: Mid

## Problem

Korean locale catalogs under `locale/ko/LC_MESSAGES/` are generated by `scripts/build_locale_ko.py` and committed, but CI never regenerates or fails on drift. PRs can add gettext strings while leaving stale `.po`/`.mo` files.

## Scope

Add CI or pytest gate that regenerates locale catalogs and fails when `locale/ko/LC_MESSAGES/*` would change. Document gate in `documents/ai/manuals/testing.md` if needed.

## Non-goals

- Translating missing KO strings (SHA-43).
- Replacing polib builder with GNU gettext.
- Changing Django locale middleware.

## Implementation Plan

1. Add contract test running `python scripts/build_locale_ko.py` and asserting clean git diff under `locale/ko/LC_MESSAGES/`.
2. Wire check into `.github/workflows/ci.yml` (new matrix task or test-fast inclusion).
3. Regenerate and commit current catalogs once gate lands.
4. Update `documents/ai/manuals/testing.md` § Locale with gate description.

## Files / Areas Likely Affected

- `scripts/build_locale_ko.py`
- `locale/ko/LC_MESSAGES/`
- `.github/workflows/ci.yml`
- `tests/unit/test_build_locale_ko_strict.py` (extend or sibling test)
- `documents/ai/manuals/testing.md`

## Validation Plan

- lint: `ruff check .`
- typecheck: `mypy django_apps config src`
- tests: new catalog freshness test + `pytest tests/unit/test_build_locale_ko_strict.py -v`
- build: `python manage.py check`
- manual verification: Introduce deliberate msgid drift locally; confirm gate fails.
