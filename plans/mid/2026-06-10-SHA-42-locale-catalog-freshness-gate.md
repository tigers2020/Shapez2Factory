# Plan: Locale catalog freshness drift gate

## Source Issue

- Linear: SHA-42
- Status at planning time: Todo
- Priority: Mid

## Problem

Korean locale catalogs are generated by `scripts/build_locale_ko.py` and committed under `locale/ko/LC_MESSAGES/` (`django.po`, `django.mo`, `djangojs.po`, `djangojs.mo`). GitHub Actions never regenerates these files or fails when they drift from current template/JS gettext sources. A PR can add or change `{% trans %}` / JS `gettext()` strings while leaving stale committed catalogs and still pass CI.

## Scope

Add a CI or pytest gate that regenerates locale catalogs and fails when `locale/ko/LC_MESSAGES/*` would change. Document the gate in `documents/ai/manuals/testing.md`. Regenerate and commit current catalogs once the gate lands.

## Non-goals

- Translating missing KO strings (separate i18n backlog; see SHA-43)
- Replacing the polib-based builder with GNU gettext
- Changing runtime Django locale middleware behavior

## Implementation Plan

1. **Add contract test for catalog freshness**
   - Create `tests/unit/test_locale_catalog_freshness.py` (or extend `tests/unit/test_build_locale_ko_strict.py` if co-location is preferred).
   - Test flow:
     - Snapshot hashes or byte content of the four files under `locale/ko/LC_MESSAGES/` before builder run (or use `git diff` after run).
     - Run `python scripts/build_locale_ko.py` from repo root via `subprocess` (same pattern as `test_build_locale_ko_strict_exits_zero`).
     - Assert no diff under `locale/ko/LC_MESSAGES/` — e.g. `git diff --exit-code locale/ko/LC_MESSAGES/` or compare file hashes before/after.
   - Mark test `@pytest.mark.unit` so it runs in CI `test-fast` matrix without a separate workflow job.
   - On failure, assertion message should tell developers to run `python scripts/build_locale_ko.py` and commit the four catalog files.

2. **Verify gate fails on known drift (local repro)**
   - Before landing regenerated catalogs, run builder locally and confirm `git diff --stat locale/` shows changes (issue cites msgids like `No runs yet`, `Paste a blueprint and run the solver.`, `Layer summaries appear after a solver run.`).
   - Run new test — expect FAIL until step 3.

3. **Regenerate and commit catalogs**
   - Run `python scripts/build_locale_ko.py` from repo root.
   - Commit all four files: `django.po`, `django.mo`, `djangojs.po`, `djangojs.mo`.
   - Re-run new test — expect PASS.
   - Existing `test_build_locale_ko_strict_exits_zero` (`--strict` for `public_pages.py` KO dict) must remain green.

4. **CI wiring (minimal)**
   - Prefer relying on `test-fast` pytest discovery (no `ci.yml` change) if the new test is marked `unit`.
   - Only add a dedicated `ci.yml` matrix task if the test cannot run in `test-fast` (e.g. needs git metadata). If added, use task name `locale-catalog` running `pytest tests/unit/test_locale_catalog_freshness.py -v`.

5. **Document the gate**
   - Update `documents/ai/manuals/testing.md` § Locale (`ko`) to state:
     - `build_locale_ko.py` must be run after template/JS gettext changes.
     - CI enforces committed catalog freshness via the new contract test (distinct from `--strict` KO dict completeness).
   - Cross-reference related drift issues SHA-35, SHA-40, SHA-44 if a committed-artifacts subsection exists or is added nearby.

## Risks / Open Questions

- Builder warnings for missing KO mappings are non-fatal today; drift gate checks file output only, not translation completeness (SHA-43).
- `.mo` binary diffs can be noisy across platforms; builder uses polib — confirm deterministic output on Linux CI (ubuntu-latest).
- If `git diff` in test requires a git repo, ensure pytest temp dirs or run in-repo (subprocess cwd=root) — avoid false passes in shallow checkouts.
