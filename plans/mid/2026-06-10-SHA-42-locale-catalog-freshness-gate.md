# Plan: CI locale catalog freshness gate

## Source Issue

- Linear: SHA-42
- Status at planning time: Todo
- Priority: Mid

## Problem

Korean locale catalogs are generated by `scripts/build_locale_ko.py` and committed under `locale/ko/LC_MESSAGES/`. GitHub Actions never regenerates these files or fails when they drift from current template/JS gettext sources.

## Scope

Add a CI or pytest gate that regenerates locale catalogs and fails when `locale/ko/LC_MESSAGES/*` would change. Document the gate in `documents/ai/manuals/testing.md` if needed.

## Non-goals

- Translating missing KO strings (SHA-43)
- Replacing the polib-based builder with GNU gettext
- Changing runtime Django locale middleware behavior

## Implementation Plan

1. Add a contract test in `tests/unit/test_build_locale_ko_strict.py` or new `test_locale_catalog_freshness.py` that runs `python scripts/build_locale_ko.py` and asserts `git diff --exit-code locale/ko/LC_MESSAGES/`.
2. Wire into `.github/workflows/ci.yml` as matrix task `locale-freshness` or include in `test-fast` via pytest marker.
3. On master, run builder and commit any current drift once gate lands.
4. Update `documents/ai/manuals/testing.md` § Locale with CI gate reference.

## Files / Areas Likely Affected

- `.github/workflows/ci.yml`
- `scripts/build_locale_ko.py` (read-only)
- `locale/ko/LC_MESSAGES/django.po`, `django.mo`, `djangojs.po`, `djangojs.mo`
- `tests/unit/test_build_locale_ko_strict.py` or new freshness test
- `documents/ai/manuals/testing.md`

## Validation Plan

- tests: new freshness contract test + existing `test_build_locale_ko_strict.py`
- build: `python scripts/build_locale_ko.py && git diff --exit-code locale/ko/LC_MESSAGES/`
- manual verification: add a `{% trans %}` string, confirm gate fails without rebuild
